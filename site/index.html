Three commands, plain words for the rest

Write @jingbong in a comment. A 👀 means it picked up the request, and it replies in the same thread.

@jingbong cp

Checkpoint

Reads the whole issue and replies with a suggested title, a write-up of what's been decided, and the open questions. React ✅ to copy it into the issue.

@jingbong opt

Options

Lays out every reasonable way to settle a question, with pros and cons and no recommendation. 👍 the one you pick. Or just react 🤔 on any comment.

@jingbong build

Build

Implements the issue on a fresh branch, runs the checks, and opens one PR per changed repo. It never merges; that's up to you.

@jingbong <anything>

Ask

Ask a question about the code or request work in plain words. It can read every repository configured for the workspace.

From discussion to pull request

The suggested flow keeps the issue description as the single source of truth.

  1. DiscussTalk it through on the issue as usual.
  2. Checkpoint@jingbong cp sums up and asks what's still open.
  3. DecideAnswer in-thread. Stuck? opt or 🤔.
  4. Apply✅ the write-up to update the title and description.
  5. Build@jingbong build, then review the PR.

Runs on your machine

Jingbong creates an isolated Git worktree for each request and runs the agent CLI you choose against it.

Bring your own agent

OpenCode, Claude Code, Codex, Gemini or Cursor.

Multi-repo aware

Picks which repos an issue touches. A PR in a public repo never mentions a private one.

Never overwrites

Every build gets a new branch and PR. Failing checks open as a draft.

Stays in its lane

It never changes issue status and never merges anything.

Get started

See the self-hosting guide and comment-mode setup for Linear and GitHub configuration.

# clone and build
git clone https://github.com/north-shore-software/jingbong.git
cd jingbong
pnpm install
pnpm build
